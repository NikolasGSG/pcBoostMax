GameBoostApex EXE Return Codes

Documentation of every process exit code emitted by GameBoostApex.exe. Used by deployment scripts, MDM systems, silent-installer wrappers, and the Microsoft Store certification team.

Last updated: 2026-04-28 · Applies to: GameBoostApex 2.1.0 and later.

Summary table

Code Symbol Meaning
0 EXIT_SUCCESS Normal termination. The requested operation completed successfully or there was nothing to do.
1 EXIT_FAILURE Generic command-specific failure. One or more sub-operations could not be completed. Always accompanied by a human-readable message on stderr.
2 EXIT_INVALID The CLI command, sub-command, or argument was not recognised. Equivalent to argparse's SystemExit(2).
130 EXIT_CANCELLED The user interrupted the operation with Ctrl+C (SIGINT). Standard POSIX convention 128 + signal_number.

Installer (GameBoostApex-X.Y.Z-Setup.exe) behaviour

The Inno Setup installer is silent by default in compliance with Microsoft Store Policy 10.2.9. Launching it without any command-line arguments performs a complete unattended per-user install with no visible UI (UAC may still appear if the system is configured to require elevation).

Flag Behaviour
(no flags) Silent install. Setup re-spawns itself with /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /NOCANCEL and exits the visible instance immediately. This is the path the Microsoft Store certification harness exercises.
/UI Force the classic interactive wizard. Intended for developers and IT admins; not used by the Store.
/SILENT Standard Inno Setup silent mode (progress bar shown).
/VERYSILENT Standard Inno Setup very-silent mode (no UI at all).
/LOG="path" Write a verbose install log to path.
/DIR="path" Override the per-user install directory (default %LocalAppData%\Programs\GameBoostApex).

Setup exits 0 on success and a non-zero Inno Setup installer code on failure (see Inno Setup exit codes).

Note for installers and silent-deploy wrappers. Exit code 0 is the only value that indicates a successful install or apply step. Any non-zero value should be treated as a recoverable failure unless the documentation here flags it otherwise.

Per-command details

GUI launch — no --cli flag

Launching GameBoostApex.exe without arguments opens the Qt graphical interface. The process returns 0 when the user closes the main window normally, or 1 if a fatal Qt exception occurred during start-up (for example, no display server in Windows Server Core). The detail of any fatal exception is written to %APPDATA%\GameBoostApex\logs\gameboostapex.log.

--cli optimize

0Plan generated (dry-run) or applied with no failed actions.
1One or more rules failed to apply. The exit message lists how many succeeded vs failed.

--cli diagnose <symptom>

0Diagnosis run completed (regardless of whether issues were found).

--cli inspect <target>

0Inspection completed (findings printed; absence of findings is also success).

--cli bench <kind>

0Benchmark completed.
1Boot benchmark failed (typically permissions — Get-WinEvent without admin).

--cli memory <action>

0Status reported, or trim attempted (partial trim still returns 0).

--cli rollback <scope>

0Rollback completed (or there was nothing to roll back).
1The targeted rollback action failed. Run GameBoostApex --cli rollback session to retry.

--cli services <action>

0List, recommendations, or restore completed.
1One or more service changes could not be applied (insufficient privileges or pinned by Group Policy).

System-level codes that can also surface

These are not emitted by GameBoostApex itself, but by the Windows kernel / C runtime if the process terminates abnormally. They are documented here for completeness.

Hex / DecimalMeaning
0xC0000005
3221225477		 Access violation — corrupted memory write. Please file a bug report at the issues tracker with steps to reproduce.
0xC000007B
3221225595		 Invalid image format — antivirus quarantined a runtime DLL or the binary download was corrupted. Re-download the .exe and verify the SHA256 published next to the release.
0xC0000409
3221266694		 Stack buffer overrun. Reported as a Qt teardown race in PyInstaller 6.x — fully mitigated in GameBoostApex 2.1.0 and later by an explicit os._exit() from the CLI path.

How to capture the exit code

PowerShell

$proc = Start-Process -FilePath ".\GameBoostApex.exe" `
    -ArgumentList "--cli","services","list" `
    -Wait -PassThru -WindowStyle Hidden
$proc.ExitCode  # 0 on success

Note: the PowerShell & call operator returns $LASTEXITCODE as $null for the windowed-subsystem GameBoostApex.exe because the C runtime detaches stdio. Use Start-Process -Wait -PassThru instead — it reads the exit code via GetExitCodeProcess at the kernel level.

Command Prompt (cmd.exe)

GameBoostApex.exe --cli optimize --plan max-perf
echo %ERRORLEVEL%

Python subprocess

import subprocess
result = subprocess.run(
    ["GameBoostApex.exe", "--cli", "bench", "ping"],
    capture_output=True, text=True, check=False,
)
print(result.returncode)  # 0 on success

GameBoostApex is open-source. The canonical source for these codes is app/cli/runner.py in the public repository.
